# 在线 AI 配置与调用审计设计

## 背景与目标

主设计已确认报告分析支持“在线模型 / 离线规则”两种模式，在线调用失败时必须自动回退。目前系统虽有模式选择和 HTTP 客户端，但仅发送自定义 `summary` JSON、直接返回原始响应，无法正确读取 OpenAI 兼容接口的 `choices[0].message.content`，也没有可维护的模型设置和失败审计。

本次实现补齐以下闭环：

- 管理员可在中文页面维护在线模型端点和模型名称，并测试当前配置。
- API 密钥只从 `STUDY_COLLECTION_AI_API_KEY` 环境变量读取，不写入数据库、日志或接口响应。
- 在线报告使用 OpenAI 兼容 Chat Completions 请求和响应格式。
- 每次在线调用都记录用途、用户、模型、结果、耗时和脱敏失败原因。
- 配置缺失、远端失败、超时或空响应都不阻断报告生成，仍自动回退离线规则。

## 方案比较

1. **仅使用环境变量。** 实现最小，但管理员无法在页面确认当前模型和调用状态，也不能满足配置与审计要求。
2. **端点、模型和密钥全部保存数据库。** 使用方便，但本地数据库泄漏会直接暴露模型密钥，且需要额外密钥加密与轮换体系。
3. **数据库保存非敏感设置，密钥使用环境变量。** 管理员可维护端点和模型，密钥不落库；本地部署仍可通过启动环境安全注入。采用此方案。

## 架构

`ai-service` 增加设置、OpenAI 兼容客户端、调用审计和管理员 API。设置仓储在无数据库模式使用内存实现，在 `local-mysql` 模式使用 MySQL；两种模式均以环境变量作为默认值。`AiAnalysisService` 负责调用编排、耗时统计、审计写入和规则回退，`report-service` 继续只负责构造学习摘要与保存报告。

在线调用流程：

1. 用户在报告页选择在线模型并提交。
2. `LearningReportService` 将当前用户、用途 `LEARNING_REPORT` 和分析摘要交给 `AiAnalysisService`。
3. 客户端读取当前有效设置，发送 Chat Completions 请求。
4. 成功时提取首个非空文本内容并保存 `SUCCESS` 审计；失败时保存 `FALLBACK` 审计并返回规则建议。
5. 报告仍保存实际来源 `ONLINE_MODEL` 或 `RULES`，历史报告行为不变。

## 数据模型

### `ai_model_settings`

单例设置表，固定主键 `id = 1`：

- `provider`：第一版固定 `OPENAI_COMPATIBLE`。
- `endpoint`：完整 Chat Completions 地址，支持 `http` 与 `https`，便于本地模型。
- `model_name`：请求中的模型名称。
- `updated_by`、`updated_at`：最后修改人和时间。

API 返回额外派生字段 `apiKeyConfigured`，只表示环境变量是否存在。

### `ai_call_audits`

- `user_id`：发起调用的用户；配置测试记录管理员编号。
- `purpose`：`LEARNING_REPORT` 或 `CONFIG_TEST`。
- `provider`、`model_name`：调用时实际配置快照。
- `status`：`SUCCESS` 或 `FALLBACK`。
- `failure_reason`：脱敏并截断后的失败原因，成功时为空。
- `duration_ms`、`created_at`：耗时与时间。

审计不保存提示词、模型输出、Authorization 请求头或 API 密钥。

## 接口与权限

- `GET /ai/settings`：管理员读取当前有效设置。
- `PUT /ai/settings`：管理员更新端点和模型名称。
- `POST /ai/settings/test`：管理员使用当前设置执行最小测试调用，并写入审计。
- `GET /ai/audits?limit=50`：管理员查看最近调用，数量限制为 1 到 100。

四个接口都使用现有 `@AdminOnly` 服务端权限，不依赖前端隐藏。

## 前端

新增管理员路由 `/ai-settings` 和“AI 设置”导航入口。页面包含：

- 在线模型状态、提供方、端点、模型名称和密钥是否已通过环境变量配置。
- 保存设置与测试连接两个明确命令。
- 最近调用审计表，展示用途、状态、模型、耗时、失败原因和时间。
- 手机端表单纵向排列，审计表在自身容器内横向滚动，不产生页面级横向溢出。

普通用户不能进入该路由，也不能调用管理接口；报告页现有在线/离线模式选择保持不变。

## 错误与安全

- 端点必须是合法的 `http` 或 `https` URI，且不能包含用户信息；模型名称不能为空。
- 未配置端点、模型或 API 密钥时，测试连接返回清晰错误；在线报告则记录失败并回退规则。
- HTTP 非 2xx、超时、网络异常、JSON 无法解析或文本为空都归一为可审计失败。
- 对外错误和审计原因不包含密钥、完整响应正文或异常堆栈。
